# GeoLibre Poster Studio

GeoLibre 的独立地图海报插件。城市线稿与街区版画共用一个编辑器，提供暖陶、青绿、暮蓝、墨色配色；地图来自真实 OpenStreetMap 数据。

## 安装

1. 在 GeoLibre 3.3.0 的 **Manage Plugins → Settings → Install from file** 中选择 `artifacts/poster-studio-0.5.0.zip`。
2. 在 **Plugins → Installed** 中启用 **Poster Studio · 地图海报**。
3. 从 **Poster Studio → 地图海报工坊** 打开编辑器。

插件关闭后可以从菜单重新打开。退出插件会移除菜单、弹窗并取消未完成的地图请求。CSS 与字体封装在 Shadow DOM 中。

## 使用

- 默认南京示例完整内置，默认选点地图与海报不需要联网。输入「南京」可以重新载入。
- 搜索城市名，选择搜索结果；或输入 `纬度, 经度`。新地点按当前纸张、模板和比例尺取景，并在周围增加 15% 余量。
- 插件内的「当前地图」读取 GeoLibre 视图中心与范围。范围过大时会提示先放大地图。
- 左侧点击地图或拖动图钉选定海报中心，中间实时显示海报；虚线取景框与圆形/矩形模板一致。地图可拖动、缩放，也可开启「在线街道与地名」浏览其他区域。
- 「比例尺」支持滑杆与数值输入，范围为 1:5,000–1:40,000，并显示实际地面宽度。数值输入按回车或离开输入框生效。比例尺按地图中心纬度与所选纸张毫米尺寸计算，适用于 100% 原尺寸打印；Web Mercator 在远离中心处有比例尺变化。
- 选点、比例尺或纸张改变后，已有数据覆盖范围内即时重绘。超出覆盖范围时延迟 650 ms 自动补载，支持取消、重试；新请求取消旧请求。补载完成前保留当前选点的部分预览，并禁用保存和导出。
- 保留四套配色，另可单独设置纸张、底色、水域、绿地、道路、建筑、文字。点击色块选择颜色，或输入 #RRGGBB 后回车确认。选择新配色或「恢复配色」会清除自定义覆盖。建筑自定义为统一颜色，模板默认保留多色建筑。
- 切换模板、标题、副标题、纸张会同步更新预览。
- 「保存草稿」通过 IndexedDB 保存地图与设置。GeoLibre 项目状态也包含当前作品。两个入口的草稿分别保存在各自网站或应用的存储中。
- SVG 保留真实矢量几何与可编辑文字；A3 尺寸为 297 × 420 mm。
- PNG 按纸张尺寸生成 300 dpi 图像，并写入分辨率元数据。A3 为 3508 × 4961 像素。

在线搜索使用 Nominatim；地图使用公开 Overpass 节点，并有失败切换和会话缓存；缓存范围内的小范围取景可直接复用。搜索由用户明确提交，不进行自动补全请求。每个地图服务的响应及下载合计最多等待 25 秒，两个服务依次尝试；显示下载阶段、已等待秒数，支持取消和失败后直接重试；搜索失败时保留原作品；补载失败会标明数据未完整。没有 API key。

## 开发

在本目录运行 `npm ci` 安装依赖。`package-lock.json` 固定构建依赖。

```sh
npm run dev
npm run typecheck
npm run build
npm test
```

预览默认使用 `http://127.0.0.1:4173/`。构建产生 `dist/index.js` 和可安装 ZIP。可设置 `GEOLIBRE_CHECKOUT` 为已安装依赖的 GeoLibre 源码目录，额外运行真实安装器兼容性测试。

测试还覆盖纸张/纬度对应的打印比例尺、中心点取景、覆盖范围、旧草稿兼容、自定义颜色持久化与输入校验。测试覆盖几何与孔洞、标题转义、坐标与草稿校验、地图服务切换与缓存、PNG 打印分辨率、真实安装器校验，以及插件激活/关闭/恢复/注销生命周期。浏览器验证范围见英文 README。

## 数据、字体和致谢

示例范围：118.740–118.840° E，32.010–32.095° N；中心 118.7900° E、32.0525° N。包含 18,727 个要素，其中 12,142 个建筑要素、5,866 个道路要素。OSM 服务返回的数据版本为 2026-07-28，获取时间另存于 `fetchedAt`；二者不混用。

地图数据 © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright)，依据 ODbL 1.0 提供。ZIP 中附带 `data/nanjing.json`，导出海报保留署名。`scripts/prepare-sample.ts` 可从完整 Overpass `out geom` JSON 重新制作示例；六位小数保留约 0.1 m 的坐标精度。

Overpass 转 GeoJSON 模块源自 GeoLibre，MIT 许可见 `src/vendor/GEOLIBRE-LICENSE`。IBM Plex Sans 字体及 Lucide、React 许可一同打包。地图海报字体使用 Georgia、系统宋体等衬线字体；SVG 在其他设备打开时会使用该设备的字体，PNG 固定为导出时的效果。

视觉方向参考 MapToPoster、prettymaps 和 Mapiful 的地图艺术与排版思路；实现没有复制 prettymaps 的 AGPL 代码，也不使用 AI 生成的地理形状。

## 已知边界

已在本地 Chrome 和 GeoLibre 网页开发宿主中验证。Tauri 原生应用、其他浏览器尚未逐一验证。中国部分地区的建筑与绿地覆盖不完整，画面密度取决于 OSM 数据；不提供纸张纹理、PDF、批量导出或制图级符号编辑。


## v0.2.0 选点地图

交互地图使用 MapLibre GL JS（BSD-3-Clause），主程序、Worker、CSS 和字体均打包到插件中，不依赖运行时 CDN。在线地名底图由用户主动开启，使用 OpenStreetMap 标准瓦片，仅请求当前浏览视图，不提供瓦片离线下载；浏览器正常遵守服务缓存。海报仍使用矢量 OSM 数据，不包含底图瓦片。参见 [OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)。

第一版草稿继续可读，在未改比例尺前保持原先取景。新设置与自定义颜色随草稿和 GeoLibre 项目状态保存。v0.1.0 安装包保留供回退。原生 Tauri 仍需单独验证 WebGL、Worker 和网络权限；本次交付验证范围见 design-qa.md。


## v0.3.0 重要地点标记

1. 点击地图上方「添加标记」，然后在地图点击重要地点；可连续添加，最多 30 个。完成后点「调整画心」或「结束添加」。
2. 在右侧「重要地点」选择标记，编辑名称（最多 40 字符）、地点/星标/爱心/家/相机/旗帜图标、颜色与大小。
3. 直接拖动地图上的圆形标记，或点「重新选点」再点击地图。标记位置按经纬度保存，调整比例尺和画心时地理位置保持不变。
4. 名称支持自动避让及优先上/下/左/右；边缘会尝试其他位置。过密导致名称无法放入取景框时，编辑区会提示，可移动标记或关闭名称。符号之间可手动错开。
5. 可隐藏、删除标记，或撤销最近一次删除。「移至画心」将所选标记作为海报中心。取景外标记会在列表提示，保存但不导出到当前海报。
6. 标记、名称和样式随草稿与 GeoLibre 项目保存，并以矢量图形和文字加入 SVG；PNG 使用同一份 SVG 渲染。地图上的画心图钉只是取景控件。

图标使用 Lucide，授权继续随包提供。旧版本草稿兼容。没有自动推断地点含义，标记名称由用户自行填写。v0.1.0 与 v0.2.0 安装包保留。

## v0.3.1 加载反馈与超时修复

南京是内置离线样例，其他城市首次打开需要向公开 Overpass 服务请求数据。现按实际取景范围下载；超时限制同时覆盖响应头和正文读取，即使原生 fetch 忽略取消，也会退出等待。地图服务返回部分结果和 timeout remark 时不会当作完整地图导出。

本次苏州实测：公开服务出现 504/500 与下载超时；缩小范围后仍未成功。已验证超时后恢复可操作状态和重试入口，但没有证明首次加载速度提升或服务恢复。免费公开节点的可靠性仍是当前限制。参见 [Overpass 公共实例说明](https://wiki.openstreetmap.org/wiki/Overpass_API#Public_Overpass_API_instances)。

## v0.4.0 离线城市

- 右侧顶部打开「离线城市」，搜索城市（或输入纬度, 经度），选择中心 5 × 5、10 × 10、20 × 20 或 40 × 40 km 范围，点击「下载到本机」。矩形范围不等于完整行政市域，界面展示四至坐标。
- 每个分块边长不超过约 4 km，顺序下载道路、建筑、水域和绿地，每块完成即以 IndexedDB 事务保存。单块每个上游允许等待 60 秒，避免把批量预下载当作实时编辑请求。首次下载仍依赖网络和公共服务，没有保证完成时间。
- 暂停、关闭或刷新后已完成分块保留；「继续下载」跳过已保存分块。失败会停下并保留进度，不自动无限重试。空白地块也会保存，Overpass 含超时备注的部分结果不会计为完成。
- 「使用此城市」不调用地名搜索，直接从完整离线包读取当前取景涉及的分块，合并时按 OSM ID 去重。调整取景仍优先检查本机覆盖，包含范围边缘，不会因预取余量越界而错误请求网络。未完成包不会伪装为完整覆盖。
- 「保存当前已加载地图」可把当前真实地图直接存入离线库。「移除」仅删除离线缓存，保留当前作品。
- 离线库与草稿分开保存在当前浏览器／应用的当前站点中；localhost 与 127.0.0.1 是不同存储空间。清理站点数据或浏览器回收存储会移除离线包。空间不足时显示错误并保留已完成部分。
- 大城市按当前取景读取相关分块，不一次性绘制整座城市；超过 100,000 要素的取景需缩小。离线取景仍保留数据来源和 ODbL 署名，最早数据获取时间与本地包更新时间分开。

## v0.5.0 导入城市离线包

1. 打开「离线城市 → 导入离线包」，选择 `.poster-city.zip` 文件，无需解压。
2. 本地校验通过后，点击卡片上的「使用此城市」。范围内选点和调整比例尺会读取本机数据。
3. 重复导入同一个文件会复用已有包。离线包保存在当前站点的 IndexedDB，刷新后保留；不同浏览器、localhost 与 127.0.0.1 需要各自导入。

插件安装 ZIP 与城市数据 ZIP 用途不同；原始 `.osm.pbf` 须先转换，不能直接在此入口导入。导入上限为压缩后 64 MiB、展开后 256 MiB、最多 1024 块。每块有 SHA-256 与长度校验，并校验网格连续覆盖、坐标、OSM ID、来源与日期。全部检查通过后一次事务写入；写入失败则回滚。SHA-256 用于完整性检查，不是发行者签名。

苏州包采用古城附近 120.6200° E、31.3100° N 为中心的 40 × 40 km 矩形，包含道路、建筑、水域和绿地，分为 100 块。卡片显示实际范围与数据日期；此包覆盖城区及周边，不等于整个苏州行政市域。范围外会走原有在线加载流程。OSM 收录密度与现实建筑完整度可能不同。

Release 附件 `suzhou-40km.poster-city.zip`：约 8.5 MB，展开的分块数据约 39.3 MB，含 87,271 个去重后的 OSM 要素；数据日期为 2026-10-11。从原始数据重建后，江苏文件及校验记录保存在 `artifacts/osm/`。可直接导入城市 ZIP，不必重新下载或运行转换脚本。

### 从江苏 PBF 重建苏州包

下载器使用四个 HTTP Range 请求、ETag 条件与分段续传，合并后核对上游 MD5，并记录 SHA-256、下载时间和来源。原始大文件位于 `artifacts/osm/`（Git 忽略），不要手动把未校验的分段拼成成品。

```sh
python3 scripts/download-jiangsu.py
python3 -m venv /tmp/poster-osmium-env
/tmp/poster-osmium-env/bin/pip install osmium==4.3.1 shapely==2.2.0
/tmp/poster-osmium-env/bin/python scripts/build-city-package.py \
  artifacts/osm/jiangsu-2026-10-11.osm.pbf \
  --output artifacts/suzhou-40km.poster-city.zip
/tmp/poster-osmium-env/bin/python tests/test_city_builder.py
```

转换器先装配完整 way/relation 几何，再按空间相交分配到网格；跨块要素保持相同 OSM ID 与完整几何，读取时去重，多边形内环保留。数据日期读取 PBF 复制时间戳，获取日期独立记录。包内 `manifest.json` 包含来源、四至、许可、日期和各块校验值；旁边的 `.report.json` 记录要素统计、校验值及转换异常。

原始 OSM 读取和面组装使用 [Pyosmium](https://docs.osmcode.org/pyosmium/latest/user_manual/03-Working-with-Geometries/)。城市包保留 ODbL-1.0 与 OpenStreetMap 署名；运行时 ZIP 读取使用 fflate（MIT），许可随插件附带。
